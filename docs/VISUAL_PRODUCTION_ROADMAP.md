# NIGHTHAWK — Visual Production Roadmap

This roadmap is a proposed art-production sequence. It does not replace the gameplay roadmap and does not claim that any listed feature is already implemented.

## Phase A — Art direction and references
- [x] Create initial visual bible for Roms and Cleiseis from supplied references.
- [x] Define photo-to-asset workflow and proposed asset structure.
- [ ] Receive and approve references for Shadow, Douglas, Cliffhanger, Navy Blue, Rampol and Maetja.
- [ ] Approve overall visual style and character concepts.
- [ ] Confirm rights/consent for likeness references.

## Phase B — Environment materials
- [ ] Create red sand, pale sand, gravel, rock, concrete, asphalt and rusted metal materials.
- [ ] Produce tileable base-colour/normal/roughness sets where appropriate.
- [ ] Integrate one material at a time and compare in-game screenshots.
- [ ] Profile GPU memory and frame time.

## Phase C — Hero assets
- [ ] Replace placeholder weapon geometry with modular GLB weapon models.
- [ ] Create modular tactical gear and operator body kit.
- [ ] Build and rig Roms and Cleiseis.
- [ ] Validate facial likeness and animation deformation.
- [ ] Build remaining six operators after references/design approval.

## Phase D — Environment identity
- [ ] Establish one distinctive Southern African-inspired test area.
- [ ] Add modular outpost, barriers, containers, watchtower and industrial props.
- [ ] Add decals, signage and environmental storytelling.
- [ ] Add day/night and weather only after base lighting and performance are stable.

## Phase E — Polish and release readiness
- [ ] LODs, texture compression and loading fallbacks.
- [ ] Soundscape and surface-specific footstep audio.
- [ ] Consistent UI iconography and operator presentation.
- [ ] Browser compatibility and low-end hardware performance testing.
- [ ] Asset provenance and licence audit.

## Collaboration rule

Claude Code may be editing the default branch at the same time. Keep art-direction work on `art/character-visual-foundation`, avoid editing gameplay files, and merge only after reviewing the diff against the latest `main`.
